## 7562 나이트의 이동 풀이 설명
먼저 나이트가 이동할 수 있는 8가지 방향을 배열로 정의한다. 나이트는 상하로 2칸 좌우로 1칸, 또는 상하로 1칸 좌우로 2칸 이동하므로 (±1, ±2)와 (±2, ±1)의 조합이 총 8가지가 된다.

BFS 탐색은 시작 위치와 현재까지의 이동 거리를 큐에 함께 담아 진행한다. 큐에서 노드를 꺼낼 때 visited 체크를 수행하고, 해당 위치가 목적지이면 현재 거리를 바로 반환한다. 목적지가 아니라면 8가지 방향으로 이동 가능한 칸을 확인하면서, 보드 범위를 벗어나는 칸은 건너뛰고 나머지를 큐에 추가한다.

테스트케이스마다 보드 크기 L이 달라지므로 visited 배열은 BFS 함수 내부에서 매번 새로 생성해야 한다. 시작점과 목적지가 같은 경우에는 BFS 시작 직후 꺼낸 첫 노드가 이미 목적지이므로 거리 0을 반환하여 별도 예외 처리 없이 자연스럽게 처리된다.

## 풀이 과정에서의 시행착오
1. 나이트 이동 방향 배열 정의 실수
처음에는 나이트의 8가지 이동 방향을 직접 손으로 써보지 않고 암기에 의존해 작성했다. 체스 나이트는 "ㄴ자" 이동이라 2+1 조합인데, 부호 조합을 빠뜨리거나 중복 정의하는 실수가 생길 수 있다.

2. visited 체크 위치 실수
BFS에서 visited를 큐에 넣을 때 체크하는 방식과 큐에서 꺼낼 때 체크하는 방식 두 가지가 있다. 처음에는 큐에 넣을 때 체크하려 했으나, 강의 자료에 따라 패턴은 꺼낼 때 체크하는 방식을 사용했다.

3. 출발점 == 목적지 엣지 케이스
입력이 1 1 / 1 1처럼 시작과 끝이 같은 경우를 별도 처리해야 하는지 고민했다. 별도 if 없이도 BFS 로직 자체에서 처리된다.

// 큐에서 꺼낸 직후
if (r == rGoal && c == cGoal) return distance;
큐에서 처음 꺼낼 때 이미 목적지이므로 0을 반환한다. 별도 예외 처리 불필요.

4. 보드 범위 체크 순서
범위 체크를 조건 순서 없이 작성했다가 ArrayIndexOutOfBoundsException이 발생할 뻔했다. rr >= L 체크 전에 visited[rr][cc]에 접근하면 런타임 에러가 난다.

// 반드시 범위 체크를 visited 접근보다 먼저
if (rr < 0 || cc < 0 || rr >= L || cc >= L) continue;
queue.add(new int[] {rr, cc, distance + 1});
