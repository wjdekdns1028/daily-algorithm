## 1927 최소 힙 풀이 설명
배열이나 리스트에 값을 계속 넣고, 0이 나올 때마다 전체를 탐색해서 최소값을 찾는 방식으로 구현하면 최악의 경우 시간이 오래 걸릴 수 있다. 입력의 개수가 최대 100,000개이기 때문에 비효율적인 방식은 시간 초과가 날 가능성이 크다.

그래서 이 문제에서는 최소 힙(Min Heap) 자료구조를 사용하는 것이 적절하다.
Java에서는 PriorityQueue가 기본적으로 최소 힙 구조로 동작하므로, 이를 그대로 사용하면 된다.

풀이 방식은 다음과 같다.

x가 자연수이면 PriorityQueue에 넣는다.
x가 0이고,
큐가 비어 있으면 0을 출력한다.
비어 있지 않으면 가장 작은 값을 꺼내어 출력한다.

이때 출력이 여러 번 발생하므로, 매번 System.out.println()을 사용하는 대신 StringBuilder에 결과를 모아서 마지막에 한 번에 출력하면 더 효율적이다.

## 풀이 과정에서의 시행착오
처음에는 첫 줄에 입력되는 N을 보고, 이 값을 배열의 크기처럼 생각해서 연산들을 모두 저장해야 하나 고민했다.

하지만 다시 문제를 읽어 보니 N은 숫자를 저장하는 개수가 아니라 명령의 개수였다. 즉, 다음 줄부터 들어오는 값들을 하나씩 읽으면서 바로 처리하면 되는 문제였다. 그래서 별도의 배열에 모든 입력을 저장할 필요가 없다는 점을 먼저 이해해야 했다.
Java에서는 최소 힙을 직접 구현하지 않아도 PriorityQueue를 사용하면 된다는 점을 확인한 뒤, 자료구조 선택은 해결할 수 있었다.

하지만 구현 과정에서 한 번 실수한 부분이 있었다.
처음에는 x == 0일 때 pq.poll()만 호출했다. 그런데 poll()은 값을 꺼내고 제거할 뿐, 문제에서 요구하는 출력을 자동으로 해주지는 않는다.
즉, 가장 작은 값을 제거만 하고 출력하지 않는 코드가 되어 버렸다.
문제를 다시 확인해 보니 “출력하고 제거”가 조건이므로, pq.poll()의 반환값을 StringBuilder에 추가해야 한다는 점을 알게 되었다.

또 하나의 실수는 출력 형식이었다.
처음에는 sb.append(0);처럼 값만 이어 붙였는데, 이렇게 하면 출력 결과가 한 줄씩 구분되지 않고 붙어서 나오게 된다.
백준에서는 출력 형식이 정확해야 하므로, 각 결과 뒤에 '\n'을 붙여야 한다는 점도 놓치지 않아야 했다.
