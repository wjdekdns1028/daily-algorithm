## 43238 입국심사 풀이 설명
이 문제는 n명이 모든 심사를 마치는 데 걸리는 최솟값을 구하는 문제이다. 처음에는 심사관마다 순서를 직접 시뮬레이션하려 했으나, 대기 인원이 최대 10억 명이기 때문에 직접 시뮬레이션하면 시간이 너무 오래 걸린다. 따라서 이진 탐색을 활용하여 풀이하였다.

핵심 아이디어는 "T분 안에 n명을 모두 심사할 수 있는가?"라는 조건을 기준으로 이진 탐색하는 것이다. T분이 주어졌을 때 각 심사관이 처리할 수 있는 인원은 T를 해당 심사관의 심사 시간으로 나눈 몫이다. 이를 모든 심사관에 대해 합산하면 T분 안에 처리 가능한 총 인원수를 구할 수 있다. 합산 인원이 n 이상이면 시간을 줄여도 되고, n 미만이면 시간을 더 늘려야 한다.

탐색 범위는 최솟값을 1분, 최댓값을 가장 느린 심사관의 시간인 10억에 n을 곱한 값으로 설정하였다. 이는 모든 사람이 한 명의 심사관에게 처리되는 최악의 경우를 의미한다.

이진 탐색 과정에서 mid값을 기준으로 처리 가능한 인원을 계산하고, n 이상이면 answer에 mid를 저장한 뒤 탐색 범위를 줄이고, n 미만이면 탐색 범위를 늘리는 방식으로 반복하여 최솟값을 구하였다.

## 풀이 과정에서의 시행착오
처음에는 심사관마다 순서를 직접 배정하는 시뮬레이션 방식으로 접근하였다. 그러나 대기 인원이 최대 10억 명에 달하기 때문에 이 방식으로는 시간 초과가 발생할 수밖에 없다는 것을 깨닫고, 이진 탐색으로 방향을 전환하였다.

이진 탐색으로 방향을 잡은 뒤에는 탐색의 기준을 무엇으로 삼을지 고민하였다. 결국 특정 시간 T가 주어졌을 때 n명을 모두 처리할 수 있는지를 판별하는 함수를 만들고, 이를 기준으로 탐색하는 방식이 적합하다는 것을 파악하였다.

자료형 문제도 있었다. n과 times의 값이 모두 최대 10억이기 때문에 이를 곱하면 int 범위를 초과한다. 처음에 int로 선언하였다가 오버플로우가 발생하였고, left, right, mid, count, answer 모두 long으로 수정하여 해결하였다.

또한 count를 합산하는 과정에서도 오버플로우가 발생할 수 있다는 점을 고려하여, count가 n을 초과하는 순간 반복을 중단하도록 처리하였다.
